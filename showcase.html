Text Editor in C

A console-based line editor using linked lists, dynamic memory allocation, and file I/O

C Language Linked List Dynamic Memory File I/O

Project Overview

A menu-driven console text editor where each line of text is stored as a node in a singly linked list. The user can insert, delete, edit, display, save, and load lines through numbered menu options. All memory is dynamically allocated and freed before exit, making it Valgrind-clean.

C Features & Concepts Used

ConceptWhere it appears

Singly Linked ListLines are chained via next pointers; head points to the first node

Pointer traversalEvery function walks the list with current = current->next
fopen / fcloseSave opens in write mode "w", load opens in read mode "r"
fprintf / fgetsWrite lines to file; read lines from file
strcpy / strcspnCopy text into nodes; strip the newline character from input

Global variableshead and total_lines are accessible by all functions
#define macroMAX_LINE 1024 sets the maximum characters per line

Algorithm

Main Program Loop

1.Display 8-option menu
2.Read user's integer choice with scanf
3.Dispatch to the matching function via switch-case
4.Repeat until user chooses option 8 (Exit)

Insert at End

1.Allocate a new node with malloc
2.Copy the text into the node
3.If list is empty, set head = new_line
4.Else traverse to the last node, set last->next = new_line

Insert at Position

1.Validate position is between 1 and total_lines+1
2.If position is 1, new node becomes head
3.Else traverse to node at (position−1), rewire pointers

Delete a Line

1.Validate position is between 1 and total_lines
2.If position is 1, move head to head->next
3.Else traverse to (position−1), skip over the target node
4.Call free() on the removed node

Save / Load

1.Save: Open file in "w" mode, write each node's text with fprintf, close
2.Load: Open file in "r" mode, free existing list, read each line with fgets, insert at end

What Makes This Project Different

If another team builds a similar text editor, here are the distinguishing points of this implementation:

AspectThis projectTypical alternative
Data structureSingly linked list (dynamic size, no wasted memory)Fixed-size array of strings (wastes memory, hard limit)
Insert at positionSupported at any valid indexOften only append at end
Memory managementfree_all_lines() cleans up everything; Valgrind-cleanOften missing, causes memory leaks
File persistenceBoth save and load supportedSome only save, cannot reload
Edit in placeModify any line without deleting and re-insertingOften requires delete + insert

Conclusion

  • The project demonstrates core C concepts: structures, pointers, dynamic memory, linked lists, and file I/O
  • Every malloc has a matching free, making the program memory-safe and Valgrind-clean
  • The menu-driven design keeps the interface simple for console use
  • File operations allow data to persist across sessions
  • The linked list allows unlimited lines (bounded only by available RAM)

Limitations

  • No undo/redo — once a line is deleted or edited, the old content is gone
  • Line length cap — each line is limited to 1024 characters (MAX_LINE)
  • No search — cannot find a word or line by content
  • Sequential access — reaching line N requires traversing N−1 nodes (O(n) per operation)
  • No cursor movement — this is a line editor, not a character-level editor like vim or nano
  • Single file at a time — no tabs or multiple buffers
  • No syntax highlighting — all text is treated as plain text
  • No auto-save — user must explicitly choose save before exiting

Compile & Run

gcc -o text_editor text_editor.c
./text_editor

Check for Memory Leaks

valgrind --leak-check=full ./text_editor

Expected output: All heap blocks were freed -- no leaks are possible
